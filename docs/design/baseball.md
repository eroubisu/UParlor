# 棒球（1v1）设计定稿

按用户 2026-10-14 的确认：Super Mega Baseball 的**读心与资源博弈**保留，**实时手感换成"格"**；
垒包画成正方形、外野画成一条线（左下角是本垒）；接球由玩家手动完成；防守方先布阵；
外野线只显示最有把握的野手，漏接与野手属性挂钩。

## 硬约束（TUI）

1. 没有连续时间与帧循环，只有离散事件。
2. 远程手柄延迟 50–300ms，任何要求 200ms 内精度的操作都会变成运气。
3. 空间只能"选格"，九宫格式的瞄准会退化成抽奖。
4. 文字界面强在序列与历史，弱在动作 —— 所以博弈靠"读历史 + 推理"。

## 单球流程

```
布阵 / 投球（守方）：布阵 → 球种(5) → 区域带(3) → 力度(2) → 跑者(2，垒上有人才有) → 确定（再确认一次）
  → 打击（攻方）：预判球种(5) → 挥棒类型(3: 标准/大力/滚地球) → 盗垒(垒上有人才有) → 确定（再确认一次）
    （两张表单同一个顺序：设置项在前、确定在最后；2026-10-17 重构时统一，原来打击表单是「确定」在盗垒前）
  → 两边都交牌后：棋盘中间那一槽的两盏灯都亮（不另发播报，灯就是提示）
  → **倒数 3→2→1**（每秒一跳，画在棋盘上投打行的右竖线右边、贴棋盘右边缘）——
    数完**不自动投**：投手那边亮起「投球」键，他按下这一球才投出去
    （用户 2026-10-16 定：这颗键只是"投出去"的确认，按下的时机不算进任何判定）；
    这几秒谁也不能改牌（`pending` 锁着，两个灯继续亮）
  → 交牌那一刻双方的键就都出来了（投手的「投球」/ 打者的「击球」），只是都还没亮
  → 投球段：9 帧 ×140ms ≈ 1.26 秒（球从右往左飞）；**打者整段都能按「击球」，
    按下的那一帧就是时机档（提前 / 正常 / 延后），按下瞬间按钮换成跑垒布局**
  → 挥棒段：3 帧 ×140ms ≈ 0.42 秒（球到本垒，本垒符号按结果变）；
    **击球键这时也不消失**（用户 2026-10-15：一消失就会误触旁边的选项），
    这时候再按＝「延后」——球已经到板前，那一挥通常没好结果
  → 没按＝这一球放过去（判好坏球）；按了但打不着照旧挥空
  → 机器人打者也走同一条路：它按自己的读球结果排一个帧（`_plan_press`），到点按下
    （它不主动放过去；放过去只属于真人玩家：不按就是放过去，播报写「未挥棒」）
  → 最后一帧才揭晓进垒点 / 好坏球 / 挥空 / 界外 / 击出；动画期间打者看不到球种、双方都看不到结果
    （盗垒也是交牌内容：开投之前对手的数据里没有任何起跑痕迹，开投后才画起跑的人）
  → 揭晓时日志里这一球只占一行，结果之后跟两个事实词组（2026-10-17 用户定）：
    `时机提前 预判正确`（只在打者挥了棒时写；只陈述事实，不评价、不给建议）
  → 投打行的两条分界线（2026-10-17 用户定）：球路上用淡色 `┆` 画出 提前 / 正常 / 延后 的分界，
    球越过线的那一刻就换档；打者一按下击球，本垒处亮起实心金点（挥棒是公开动作，双方都看得到）
  → 击出后：打者与被挤的人自动开跑，进入外野线逐格飞行；守方追球（匀速连续地跑）+ 回车起跳接球，攻方指挥跑垒
  → 飞球被接住＝接杀出局（提前离垒的人可能被双杀）；落地／滚地则进入捡球＋传垒（不再是安打）
  → **滚地球永远不会被判接杀**（用户 2026-10-15 纠正）：它是地面球、滚到野手脚边，
    野手捡起来传垒，打者要在一垒**被封杀**才算出去；球到得比人慢就是内野安打，
    垒上跑者借这次传球推进（三垒有人时就是野手选择打点）
  → 捡球：野手跑到落点 → 传球菜单（四个垒包 + 距离 + 不传）→ 传球计时 → 封杀 / 安全
  → 结算得分与垒上跑者
```

**三项挥棒（用户 2026-10-15 定：不要「等球」选项）**：`标准挥击 Standard Swing` /
`大力挥击 Power Swing` / `滚地球 Ground Ball`。菜单只写名字，作用自己研究（见「挥棒与选球」）。
放过去＝不按击球键（服务端内部仍用 `take`，播报写「未挥棒」）。

**出牌顺序（2026-10-15 用户定档）**：两边**同时**各自出菜单，自己按「确定 → 是」交牌；
交牌前随便改、交牌那一球锁定（布阵也在交牌前随便改）。两边都交了才开动画。
**关键设计**：双方的选择互相不可见（同时提交 + 只给本人看）：

- 投手的球种 / 区域 / 力度只发给投手，打者屏幕上不出现（否则"预判球种"就没得猜了）；
  打者要的信息只有球数、侦察板（已经打完的球）与棋盘上的公开状态。
- 每一方只会看到自己的菜单：投球菜单只给守方，打击菜单只给攻方，飞行/捡球的跑位与接球
  动作只给守方，跑垒指令只给攻方。盗垒是打击表单里的一项（垒上有人时才出现）。
- 两边都实时收到棋盘更新（含对方行动造成的阶段变化与比赛结束的结算）。
- **交牌灯在棋盘方框中间那一槽**：空心圆＝这一方还没交牌，实心绿灯＝已交牌
  （2026-10-16 从右栏「就绪」行搬到棋盘上，和这条"实时状态都在棋盘"的规则一致）。
  上一拍的判定不和灯共用这一槽（2026-11-15）：判定在倒数槽上方自己的一槽，所以出结果后
  下一球的出牌阶段灯照旧在原位。

## 操作模型（与飞行棋/UNO 一致）

- 游戏动作走**棋盘下方的操作区**，两种形态：
  1. **按钮盘**（跑位 / 跑垒 / 接球 / 传球）：见「飞行与捡球操作」，光标挪到哪个按钮就执行哪个。
  2. **一列设置菜单**（投球：布阵 / 球种 / 区域 / 力度 /（垒上有人才有）跑者 / 确定；
     打击：预判 / 挥棒 /（垒上有人才有）盗垒 / 确定）：
     进设置项是二级菜单（列出取值 + **返回**），选完自动回到一级，可以接着选下一项；
     最后一项「确定」提交前再问一次，菜单只有「是 / 否」两项，这一列仍然用回车提交。
     **交牌那一刻就关掉确认菜单、回到当前阶段的菜单**（用户 2026-10-15：定完还停在"是/否"上，
     既看不到下一步，也挡着操作）。
     菜单本身用的是引擎自带的 `SelectList`（`window_engine/primitives.py`），
     前缀与配色跟房间菜单、UNO 完全同一套参数（`idle_prefix=ICON_INDENT` + 主文字/三级文字色）。
- **二级菜单只写取值的名字**（用户 2026-10-15 定档：选项的作用是玩家该自己研究的东西，
  菜单不印概率、不印效果、不替玩家算账）：如 `好球带边缘`、`大力挥击`、`外野退守`。
  想知道这些值值什么，去看帮助、看侦察页最近几球发生了什么。
  操作区固定 **8 行**（2026-10-15 用户定档）：第一行是**子菜单标题**（二级菜单写它自己的名字，
  如「球种」；一级主盘与按钮盘留空），下面 7 行是内容。高度固定 8 行，换菜单不会让棋盘长高变矮。
- 菜单只写**标签 + 数据**：设置类菜单是 `> 布阵  标准站位`、`> 力道  标准`；
  操作面板的按钮只写动作名（`传二垒`、`左移`），距离、覆盖格数这类说明性数据
  写在棋盘上或留在帮助/记录里（操作面板不写第二列解释）。
  二级菜单也只有取值名字，**不写任何"这个值值什么"**——那是玩家自己研究的部分。
  不写任何解释性句子（没有「已选」「不改这一项」「按当前设置投出」这类废话），
  也不写成按键说明。
- `← →`（或 `↑ ↓`）移动游标、`Enter` 执行；按钮盘同一套键位，
  区别只是按钮盘里**光标落下就等于执行**（传垒那行仍要回车）。退出菜单靠二级菜单的「返回」
  （Esc 在本项目里是"关掉最上层浮窗"的全局操作，不承担游戏内返回）。
- 布阵选中即刻发给服务端（它不消耗行动，菜单可以接着用；动画期间的预告里挑的布阵先留在本地，
  守方真的开始下一球时再同步）；其余参数留在本地，
  提交时一次性拼成完整指令（`/pitch 球种 区域 力度 跑者`、`/swing 预判 挥棒 盗垒`）。
  垒上没人时跑者 / 盗垒项不出现，指令里一律是中立值（`no` / `hold`），服务端同样归一。
- **交过一次牌之后，下一球的表单光标直接停在「确定」**（2026-10-17 用户定）：原样再来一球
  只要 回车 → 回车；开局第一球仍从第一项开始设置。上一球的设置整场保留。
- **击球是按键而不是选项（2026-10-15 用户定档）**：投球段里打者的操作区换成一颗「击球」键，
  按下去时把**客户端插值出来的当前帧**随 `/hit <帧>` 报给服务端，作网络延迟的参考；
  **时机档由服务端校验后定档**（2026-10-17 用户定档：防作弊 + 补偿延迟）——
  服务端只把报来的帧往回认最多 `HIT_LATENCY_TOLERANCE_FRAMES`＝2 帧（≈280ms，
  盖得住正常延迟）；报未来、报得比这还早、或报的不是数字，一律按服务端当前帧算，
  伪造完美时机行不通。定档规则不变：`rules.swing_timing(帧, 总帧)`
  （前 45%＝提前、前 80%＝正常、其余＝延后）。
  按下那一刻本地就把菜单换成跑垒盘（默认停在「前进」），不用等回执。
  按键只吃回车（和传垒同一类）：它要你在球到的那一刻按，光标落上去不算数。
  打者不按＝这一球放过去（判好坏球），不是挥空。
  **键什么时候出现、什么时候能按（用户 2026-10-15 定）**：交牌那一刻（服务端 `ready` 灯亮）
  这颗键就出来——等对手交牌、以及倒数 3→2→1 期间都看得见，让玩家先站好位；但那几秒
  `my_turn` 是假（键是暗的），**按了不发货、也不弹提示**（`on_nav` 在非本方回合直接返回）；
  开投那一刻键亮起来，同一个 `root_kind='hit'` 一路带过去，游标不跳。
  键跟着挥棒走：按过一次（`delivery.swung`）或阶段结束就换成跑垒盘。
- 右下角面板只放房间级操作（放弃）；玩法动作全在棋盘下方的操作区菜单里。
- 非本方回合整张菜单置灰，回车无效；已提交的动作在下一次服务器回执前不再响应。
- 游标默认停在当前取值上（布阵＝当前站位）；二级菜单的返回项不改任何取值。

## 飞行与捡球操作（唯一有时间压力的一段）

这一段的动作**画成按钮**（和 UNO 的出牌按钮同一种框），只有一行。
**中立项（停止 / 保持 / 不传）夹在左右两个方向之间**，这样 `←` `→` 挪光标时正好对上左/右：

| 按钮盘 | 守备方 | 进攻方 |
| --- | --- | --- |
| 飞行中 | `左移` `停止` `右移`（光标落下就朝那个方向匀速跑；**回车＝起跳**） | `撤回` `停止` `前进` |
| 捡球 | `左移` `停止` `右移`（回车没有动作） | — |
| 捡球到球位后 | `传一垒` `传二垒` `传三垒` `传本垒` `不传` | — |

**方向键只用来选择选项（用户 2026-10-15 定档）**：规则本身住在
[游戏设计原则的 Selection-first 一节](../../design/game-design-principles.md#selection-first-interaction)
（操作面板的唯一范围例外：可撤销动作光标落下即生效，不可撤销动作仍要回车）。
本页只记棒球这边怎么落地的：

- 导航：`← →`（含 `h` / `l`）在同一行里挪一格、到行尾**环绕**回行首，`↑ ↓` 换行；
  换行本身不执行动作，换回来停在那一行当前生效的按钮上（和 UNO / Ludo / 所有菜单同一套语义）。
- 可撤销的按钮行（跑位、跑垒、盗垒）：光标落下即生效，不用回车。
  追球按钮是**持续状态**：光标落到「右移」就发一次 `/field right`，服务端记着这个方向，
  野手就一直匀速往右跑，直到光标挪到「停止」（发 `/field stop`）；客户端**不再每拍重发**。
  球比人快，所以会看到他一直跑、跑得比球慢，**不会跑到一半被系统冻住**。
- **回车＝起跳（用户 2026-10-21 定）**：不按＝小范围、高精度（左右各 1 格内稳稳接）；
  按下＝大范围、低精度（空中那一段左右各 3 格，但额外 +20% 脱手）。
  **起跳的时机算数**：球到的那一刻野手必须正好在空中（起跳后 `FIELDER_AIR_SECONDS`＝1 秒内）
  才算跳到了；跳早了落地时球还没到，白跳，还要承担缓冲。**跳一次之后要缓一缓**
  （空中 1 秒 + 落地缓冲 `FIELDER_REST_SECONDS`＝1 秒）：这 2 秒里既不能跑也不能再跳，
  回车无效、什么也不会发生。动作名按球型自动叫：滚地球＝飞扑、空中球＝跳起（只用于播报）。
  **不再有「普通 / 跳跃 / 飞扑」三选一，也没有「最合适动作」的提示。**
- 传垒那一行不可撤销：光标挪过去不发货，`Enter` 才传。
- 落地后先给跑位按钮；**野手朝球位跑到了就自动停住**，画面上一到球位就立刻换成传球按钮
  （客户端按自己在滑的位置预判，不等服务端的下一拍；传球指令仍由服务端按时钟核对）。
- **动画期间预告下一刻的菜单**（2026-10-15 用户要求"选好后下一步的选项尽早放出来，
  让玩家准备好进行操作"）：投打两段动画里双方都交完牌在等、传球途中守方也在等，
  这两处的操作区**先把下一刻的菜单放出来**（一级盘不写标题——标题只属于二级菜单），
  游标可以先摆好（`preview` 状态：能翻菜单、能摆游标，回车不提交，阶段一到就原地生效）。
  预告的只有**与结果无关**的那一套（守方的跑位盘、下一球的投球/打击表单、下一次传垒）。
  守方在投球段先拿到跑位盘不算泄密：他本来就是要去追球的人；
  **起跳（回车）与攻方的跑垒按钮等球真被击出才生效**——那之前没有球可接，
  摆上去只会误导，也等于提前把"球有没有被打中"漏给打者
  （和"动画最后一帧才揭晓"的保密契约冲突）。
- **任何阶段操作区都不许空白、不许整块灭掉**（2026-10-15 用户："按钮都要早点出来，
  让人可以去按"）。规则：手上有活 → `my_turn` 亮着；手上没活但下一步有表单 →
  `preview`（能翻能预选，发不出指令）；两种情况都不是才允许空。逐个窗口走查：
  ① 守方交完牌在等对手、② 两边交完等倒数——投球表单**原位留着**（预告），
  能先把球种/区域/力度挑好；③ 高飞被接杀后的触垒窗口——守方没动作，摆下一球的投球表单，
  攻方那边三个跑垒键是真能按的；④ 打者交完牌等开投——「击球」键在，暗的、按不动、无提示。
  唯一例外就是那颗「击球」键：它按不动时**不算预告、也不给任何提示**（用户明确要求）。
  契约测试 `test_every_phase_leaves_the_operation_panel_alive` 把①②③④与
  击出飞行 / 捡球 / 传球 / 投球段全部钉住，谁再制造空面板就会红。
- 非本方回合整张按钮盘置灰，按键无效；已提交的提交类动作在下一次服务器回执前不再响应。

## 动画（全部逐帧滑，不是一跳一跳）

- **球**：服务端一拍给一次位置，客户端在拍内按时间连续滑动（约 30fps）。
- **跑者**：同上，箭头沿垒线滑。
- **野手**：位移同样插值——他从这一格跑到下一格是滑过去的。
- **画面跟着服务端的时钟走（2026-10-21 用户定，取代 2026-10-15 的「球不超前于服务端最近一次给的位置」）**：
  服务端一拍把东西挪一步；客户端收到时就**朝「下一拍的位置」滑**
  （球 `ball+1`、跑者 `(进度+1)/所需拍数`、投打帧 `frame+1`、传球 `done+1`），
  滑动时长＝这一拍的 `tick_ms`（用共用的 `protocol/animation.py::Animator`，按**时间**走，
  不怕计时器抖动），所以滑完正好下一拍到来。效果：
  - 球出手 / 击出的瞬间就开始动（以前要等第一拍，高飞球要空等 2.24 秒）；
  - 画面球位＝服务端真实位置，只晚一个网络延迟（以前永远慢一整拍：投打 140ms、飞行 1.76–2.24 秒）；
  - 球飞到落点那一拍，画面上的球也正好到落点（以前最后一格会"跳"过去）；
  - 真实落点依旧保密：画面只往前看一步（`ball+1`），服务端在球到落点那一拍就判，
    客户端从来不知道球会不会在下一格停。
  `tick_ms` 由服务端在每次下发的棋盘里给出（没有计时中的阶段就是一个标准拍），客户端没有自己的拍长常量。
- **野手是匀速连续地跑，不是一格一跳（2026-10-21）**：服务端只记「位置、方向、速度、起跳时刻」
  （`state.Fielder`），位置按房间时钟推算（飞行阶段的速度＝整段飞行总共 3 格 ÷ 飞行时长，速度 ≥7 双倍；
  捡球阶段每拍 1 格，≥7 为 2 格）。光标落到某个方向就发一次 `/field left|right|stop`，
  服务端马上把棋盘发给两边（带着 `pos / heading / speed / goal / air / lock`），
  客户端从这个位置出发、按速度**匀速滑**（和球一样一直在动），不再等服务端每拍报一格。
  方向由服务端记着，客户端**不重发**。
  - 起跳后的**空中 / 缓冲倒计时**也一起下发（`air` / `lock`，秒）：对手的屏幕上也看得到；
    空中画成亮白、缓冲期间画成暗灰、其余时候是己方的绿。缓冲期间位置不动，缓冲完才接着跑。
  - 球落地后接着在捡球阶段跑（带着方向）；滚地球滚到了野手脚下，他站住；
    朝球位跑到了就自动停住（`goal`），背着球跑不受限制。
- **落点范围一路收窄（2026-10-21 用户定）**：球一击出，落点不再是一个带误差的圈，而是
  **一段范围**——外野线上一条细横线（`╶────╴`，金色），球越飞越近、横线越缩越短，
  窄到不足一格就收成一个虚线圈，**球到的那一拍正好停在真落点上**。
  范围一直含真落点、但真落点不在正中（偏离正中 25%–85% 半宽）；
  **打得越结实刚出手时范围越宽**（半宽 1.2 格 → 3 格，随击球质量线性增加），
  所以「打得越结实越难判断」仍然成立。棋盘中间的「飞向 …」和四个垒的传球距离都按范围正中算
  （真落点不会提前卖给守方）；客户端朝下一拍的范围滑（`span_next`），和球同一种节奏。
- **挥棒点本地先亮（2026-10-21）**：自己按下击球的瞬间，本垒处的挥棒点和跑垒盘就立刻画出来，
  不等服务端回执；回执晚到、甚至先到一份旧数据，也不会闪回"没挥"，一直保持到这一球结束。
- **击球帧按「帧号 + 帧内进度」认（2026-10-21）**：客户端报画面上的球位（带小数）；
  服务端按「当前帧号 + 这一帧已经走了几分之几」认，只往回认 2 帧容差，领先服务端的部分不认。
  房间用可替换的时钟（`room.clock`）给每一帧盖时间戳。
- **投打**：服务端两段——投球段 9 帧、挥棒段 3 帧（每帧 140ms，合计约 1.68 秒），
  客户端在帧内再插几帧；球从**右往左**飞（投手在右竖线外面、本垒在左端），到本垒后进挥棒段。
- **三条固定行（2026-10-15 用户定档：画面始终不变，只有人和球在动）**：棋盘底部永远是
  投打行 + 外野线 + 传球行，**任何阶段都不出现、不消失、不变形**。
  顺序就是用户定的「投打 → 外野 → 传球」，实现上是**一个 `ProgressTrack` 基类 +
  `PitchTrack` / `FieldTrack` / `ThrowTrack` 三个子类**（`diamond.py`）：排版（左边距、前缀、结果符号那两格、
  左右两条边界竖线、12 个格点、右竖线外面的留白）全在基类，子类只回答"这一帧这一行有什么"
  （`head()` / `marks()` / `guides()` / `_tail()`）。
  行宽由格点数决定并且**每档窗口都刚好铺满**（46/58/78/88/98 列实测一列不多不少），
  左边距与内野正方形共用 `SQUARE_INDENT`，所以整块棋盘左边是一条直线；
  三条行不可能再走样，也没有第二处重复算宽度的地方。
- **两条边界竖线 + 右竖线外面的留白（2026-10-15 用户定档）**：三条行都用 `│` 标出轨道两端，
  **两条竖线在三行上同列**（宽度全在基类算，行尾再按棋盘宽补齐）；
  右竖线外面那 3 列以上的留白里：外野行画**本垒打墙**（吃掉整段留白、铺到棋盘右边缘），
  投打行写**倒数 3→2→1**（右对齐、贴棋盘右边缘），传球行写**目标垒名**（同样右对齐）。
- **左竖线左边**：行标识（投打 / 传球 / 外野，5 列）＋**符号一格 + 空隙一格**：
  投打行那一格画本垒结果符号，另外两行同样留白；**符号和左竖线之间必须空一格**——
  贴上去就是"相切"，看着像画歪了（用户 2026-10-15 报），三行的竖线因此都在同列。
  - **投打行**：12 格球路；结果符号**保持到下一球开投**：空心圆＝这一球还没结果、叉＝挥空、
    ↗＝高飞/全垒打、→＝平飞、↘＝滚地。**投手站在右竖线外面**（和左边的本垒结果符号对称，竖线外隔一格），
    一直在（2026-10-21 用户要求：不再只在投球那两段出现、而且站在线外）；球道里没有他，球从第 12 格起飞。
  - **外野线**：球、野手、落点范围都画在这里（球越墙时停在墙上）。
  - **传球行**：传球时第 1 格＝守方野手，**球从最左一格走满整条线到最右一格**——
    整条线＝这次传球的距离（远＝拍数多、走得慢，绝不允许只走半截），
    目标垒名写在这行**右竖线右边的留白**里（和墙 / 倒数同一个位置）；
    **不传球时这一行只有格点**（不摆人、不写垒名）。
- **两列状态面板的左右缝一样宽（2026-10-16 用户定）**：`make_status_table()` 的每一行
  左右各缩进一个 `ICON_INDENT`（2 格，＝全应用其它面板的缩进标准），所以标签不贴左边框、
  数值不贴右边框，**左右两条缝一样宽**；数值彼此仍然共用同一条右边缘（右对齐）。
  放不下时先砍数值（`…`），标签永远完整。Ludo 的四项计数因此改成不留空格（`机场1赛道1跑道1完成1`）
  才塞得进缩进后的宽度。
- **字形宽度：一律按一列算（2026-10-15 实测修正）**：终端里只有中日韩文字占两列，
  **Nerd 图标、`─ │ ╭ · █ ┄`、Powerline 连接符都只占一格**——所以行内排版统一量
  `window_engine.text.cell_width`。
  实测依据（玩家机器上的 `Sarasa Term SC Nerd Font`，fontTools 读 `hmtx`）：
  `a`=500、`中`=1000、Font Awesome / Octicons 图标全部 500。
  早先按"图标两列"让位（`WIDE_GLYPHS`）反而让每一行差一格，就是用户报的"没对齐"，
  这条记录防止再走回头路。
- **宽字形要连格子一起占（2026-10-15 修）**：格点是一列一格，中文（占两列）落进去就得
  **连占两格**（`diamond._put_cell` / `_write_slot` / `ProgressTrack.render` 都按
  `cell_width(字形)` 占位）——否则这一行后面的格点、竖线、墙全部右移，
  这就是"垒包中间的文字导致没对齐"：判断槽写 `安全 SAFE`、传球行写目的垒名 `二垒`（两个汉字）
  都会命中。内野正方形与三条行的每一行宽度因此仍然完全相等（实测 46/58/78/88/98 列）。
- **左边距与正方形对齐（2026-10-15 用户定档）**：三条行、垒名行、内野正方形共用
  `SQUARE_INDENT` 一个左起点，整块棋盘左边是一条直线；行宽＝棋盘宽（左边距也算在内），
  所以右边也不多不少、墙正好到右边缘。
- **所有「球在飞」的行都是同一条进度条（2026-10-15 用户定档）**：投打、击出后的外野飞行、
  传球**共用同一个实现**（`ProgressTrack` 及其子类，见上），不是三份各写各的。
  宽度、格点、右端全在基类算，所以这几行**永远等长**（46/58/78/88/98 列下实测一致）。
- **传球也有飞行过程**：球从野手手里沿格点飞向目标垒包，进度＝已飞拍数 / 总拍数，
  整条线＝这次传球，球走满全程、最后一拍正好落在最右格（也就是判定那一刻）；
  到垒那一拍才判封杀 / 触杀 / 安全。
- **传球行右边写「垒名 距离」（2026-10-21 用户定）**：如 `二垒 15.7米`（总距离，传出去后不变）。
  右侧留白按棋盘宽是 11 / 11 / 7 / 5 / 15 列（46 / 58 / 78 / 88 / 98 宽），放不下就先去掉垒名
  （`15.7米`）、再去掉单位（`15.7`），**绝不顶宽这一行**，也不改外野格的宽度。

## 棋盘与状态面板（2026-10-14 用户定稿）

- **棋盘尺寸跟着棋盘区走**：内野正方形取棋盘区能放下的最大值（受高度限制，屏幕字符格约 2:1，
  所以"每边格数 ≈ 中间行数 × 2"才是屏幕上的正方形）；外野线是**从左到右**的 12 格，
  右端接本垒打墙（见下）。
  最小窗口（88×32，棋盘区 46×20）下棋盘恰好铺满、不出现滚动条；窗口变大时正方形与外野线一起变大。
- **内野**：四个垒包就是正方形的四个角，四条边一路画通；垒名写在方框外面
  （左上 三垒、右上 二垒、右下 一垒、左下 本垒），垒名与线之间留空格，标记不会压在线上。
  实心圆＝有人占垒、空心圆＝空垒、箭头＝正在跑向该垒、打者在本垒。
- **外野**：球从 1 号位起飞；红圆＝球、金色横线＝落点范围（缩到不足一格就是虚线圈）、野手＝人形，**不画号位数字**。
  服务端一拍只推一格，客户端朝下一拍的位置连续滑（见「动画」），
  画面球位＝服务端真实位置，只晚一个网络延迟。
- **本垒打墙在外野线右竖线外面**（不是下面，也不在另外两行）：格点铺完之后剩下的列全部归它，
  从右竖线一路铺到棋盘右边缘；另外两行在同样的列位留白（投打行那边写倒数），
  所以三行仍然等长、左右两条竖线都同列。
  墙**每一拍都在**（投打、捡球、传球时也在）——它不随阶段出现或消失。
  普通击球的红球停在外野线上；**全垒打的红球停在墙上**，这一拍保留到下一次投球前。
- **四个垒包中间是三行固定槽位（2026-10-15 用户定档）**：位置钉死在方框高度的 1/4、1/2、3/4，
  某一槽没内容就**留白**，别的内容绝不允许挤过来：
  - 槽 1＝倒数（两边交牌后 3→2→1）；
  - 槽 2＝这一拍的判定：`安全 SAFE` / `接杀 FLY OUT` / `封杀 FORCE OUT` / `触杀 TAG OUT` /
    `全垒打 HOME RUN` / `三振 STRIKEOUT` / `保送 WALK` / `双杀 DOUBLE PLAY`（开投那一刻清空），
    **按结果分色**：安全/保送＝绿、各种出局/三振/双杀＝红、全垒打＝金（2026-10-16 用户定）；
    出局按方式写清（2026-10-21 用户要求显示封杀 / 接杀，不再只写「出局 OUT」）；
  - 槽 3＝当前动作：投球 / 挥棒 / 追球 / 跑垒 / 捡球 / 传球 / 触垒（和右栏「阶段」同一个来源）。

- **跑垒**：四个垒包之间的四条边就是跑垒路线。正在跑的人是指向目标垒包的箭头

  局数 / 比分 / 出局 / 球数 / 体力——因为**其它东西棋盘上本来就在显示**：
  这一拍在干什么、交牌灯、球位、落点、野手、跑者进度、传球目标全在棋盘上

  自己刚选的投球参数也不再回显（用户 2026-10-16：右上角为什么要显示我们投球的内容）。
- **播报的写法（2026-10-22 用户定：不要中文标点，不要一句一句的）**：
  - 一件事一行，行里是**词组**，词组之间一个空格；不用 `，；：。！？（）` 连句子，也不写「于」「被」这类虚词。
    例：`封杀 一垒 打者 2出局` / `滚地球 落点中线 野手中线 飞扑恰好`。
  - **同一件事只说一次**：出局在出局那一行说，之后的收尾行只列没说过的结果
    （`打者上一垒` / `一垒跑者上二垒` / `三垒跑者得分`），站着没动的人和已经出局的人不再重复；
    「该怎么操作」这类提示不进记录（记录只写发生了什么）。
  - 计数一律 `1-2`（坏球-好球，不再写「球数」）、`2出局`、比分 `bob 4-2 alice`（客队在前）；
    只有**结算结论里自己的比分在前**（`获胜 3-1`、`落败 1-3`），读起来才和结论一致。
- **记录栏可以回看（2026-10-22 用户报：有时翻不回上一条）**：栏上留着**全部**记录，一条占一行
  （放不下的尾部用 `…` 收住，完整的一条在记录窗口里）。默认停在最新一条；
  焦点移到这一栏（shift+↑）后 `↑ ↓` 每按一次正好翻一条，下边框写 `第几条/共几条`；
  回看时新记录**不会**把视图拽走，翻回最新一条或焦点离开这一栏就又跟着最新一条走。
  这是共享的 `LogPanel`（大厅、等待室、游戏里都是它），不是棒球私有；
  记录窗口开着的时候新记录接着往下写（打开时仍是最近 16 条）。
- **上方记录栏一次只显示一行（2026-10-21 用户报）**：所有 GAME 消息都是**一行一条**
  （引擎的 `_one_line` 在出口把多行文本拆开），栏上默认停在**最后一条**，
  所以每一拍播报的**最后一行就是这一拍的结论**：

## 跑垒：一排三个按钮（2026-10-21 用户重定：连续指令，不再数「多跑几个垒」）

进攻方随时可以用一排三个按钮指挥**所有跑者**，光标落下就生效、随时可改（和野手追球同一套手感）；
**击出后默认是「前进」**（用户 2026-10-21 定：全体默认前进，要留人再叫停），
光标默认停在服务端此刻的指令上（`run_order`，重连也不会让画面说谎）：

| 按钮 | 作用 |
| --- | --- |
| 撤回 | 半路上的人调头跑回刚离开的垒；已经跑过多久，回来就要多久（调头不瞬移） |
| 停止 | 跑到下一个垒就站住；已经在半路的人先跑完这一段（半空中停不下来）；还没真正离开垒的人（刚起跑那一拍）直接留在原垒 |
| 前进 | 一个垒接一个垒往前跑，不叫停就一直跑，跑回本垒得分；原地站着的人立刻起跑 |

- 用户 2026-10-21 在「一排管所有跑者」与「两排：领跑者 / 其他人」之间选了**一排**，
  接受由此失去「只派领跑者」的选项，换更好操作。
- **被挤着必须前进的人（含打者）在第一段不能撤回、也不能留下**，选「撤回」「停止」对他们
  都只是跑到下一个垒；跑过第一个垒、继续往下一个垒的人可以回头。
  刚起跑还没离开垒的人被叫「撤回」或「停止」，就留在原垒。
- 默认前进的后果（有意为之）：击出那一刻原地站着的人也起跑，所以**高飞球被接杀时他们是「提前离垒」**，
  有被双杀的风险，也不能再借触垒窗口冒险——想「踩垒等接杀」就要在击出那一刻按「停止」。
  触垒窗口本身是一次新的决定，默认光标在「停止」（不冒险）。
- 撤回的人不是被迫进垒：球先传到他要回的那个垒就是**触杀**（不是封杀），
  `_forced_bases` / `_forced_targets` 都不把正在撤回的人算进被迫进垒。
- **击球前**（出牌阶段）盗垒写在打击表单里：进「盗垒」是「领跑者盗垒 / 保持 / 全体盗垒」，
  和别的设置一样留在本地，随 `/swing 预判 挥棒 盗垒` 一起交出（交牌后不能撤销）。
  **盗垒是秘密出牌**：投手投出这一球之前，对手的数据里没有任何起跑的痕迹。
  下达后跑者在投打两段动画里起跑（动画结束正好到垒），结果在揭晓那一帧定：
  成功＝上垒（三垒成功＝得分），失败＝被封杀出局。成功率只看跑者速度
  （`rules.steal_chance`：62% ± 每点速度 8%，夹在 20%–90%）。
  击出球时盗垒的人和所有跑者一样默认前进（盗垒的人本来就已经起跑）。
  **球被打进场内时，盗垒的人已经跑到了下一个垒（不再掷成功率），击出后的跑垒从那个新垒位起算，
  不会被拉回原垒**；盗本垒则当场得分。日志写 `盗垒成功 一垒跑者上二垒`（2026-10-22 修复）。
- **守方反制：投手的「跑者」设置**（取值用棒球里的正式说法，用户 2026-10-16 定：
  不要口语化、也不要"看不懂的简称"）：**只在垒上有人时才出现这一项**（2026-10-17 用户定：
  没人上垒时它没有对象）——投手可以选「牵制跑者」——
  成功率 **×0.5**（速度 5 从 62% 掉到 31%），代价是投手分心、打者接触率 **×1.08**
  （`STEAL_HOLD_FACTOR` / `HOLD_CONTACT_GIFT`），所以它**不是"永远更好"**。菜单只写这两个词，不写数字。
- **击出后**（飞行 / 捡球 / 传球阶段）：默认全体前进，打者、被挤的人（被迫进垒）和原地站着的人都开跑；
  指令（`/run back|stop|go`）由服务端记着、每拍照它决定
  跑到垒时是接着跑还是站住（`BaseballRoom.order`，每次击球重置为 `rules.DEFAULT_RUN_ORDER`＝前进）。
  传球到垒时球先到＝封杀，人先站稳＝安全（防守方因此可以赌一把）。
- **被迫进垒**由 `rules.forced_bases` 决定：只有从一垒连成一串的人必须往前跑
  （打者上一垒把一垒的人挤到二垒，二垒有人再挤三垒…），没有连锁的人可以选择不动。
- 野手脱手（失误）时球滚开，垒上所有人自动多跑一个垒（`_start_ground` 里 `_push_runners()`，
  与指令无关的白送一垒；已经在前进的人本来就在跑）。
- 接杀后大家回原来的垒；**提前离垒**（已经离开垒、又不是被挤着必须跑的那一段）的人可能被双杀
  （打者 + 一个跑者 = 2 出局），也不能再借触垒窗口冒险。
- 机器人：每次击球只改一次主意——多数时候第一拍就叫「停止」（站着的人留在垒上，只有被挤着的人跑），
  落后时更敢让大家跑，派出去一拍就叫停（`BaseballBot.run`）。

## 手感数字（当前节奏：投打 ×2、其余动态阶段 ×2）

现实棒球时间仅作背景参考，不是游戏内的直接换算倍率：

| 现实动作 | 真实秒数 | 参考 |
| --- | --- | --- |
| 投球到本垒 | 0.4–0.5 秒 | 时速 145 公里的球飞 18.4 米 |
| 击出的球飞 5 米 | 约 0.12 秒 | 出球时速约 145 公里 |
| 外野高飞滞空 | 3.5–5 秒 | 一支 120 米的高飞 |
| 打者跑一个垒 | 约 4 秒 | 27.4 米（90 英尺） |
| 外野回传 60 米 | 1.5–2 秒 | 时速约 130 公里 |
| 内野传球 27 米 | 0.9–1.1 秒 | 同上 |

游戏按拍离散推进。非投打动态阶段统一使用 `PHASE_SLOWDOWN = 2` 拉长各自的基准拍长；
投打动画使用 140ms/帧，倒数使用 1000ms/跳。这是游戏节奏设定，不表示所有动作与现实按同一比例缩放。

| 游戏动作 | 一格 / 一拍 | 整段 |
| --- | --- | --- |
| 滚地球 | 1760ms | 落点 2–8 → 1.76–12.32 秒 |
| 平飞球 | 1920ms | 落点 4–11 → 5.76–19.2 秒 |
| 高飞球 | 2240ms | 落点 6–12 → 11.2–24.64 秒 |
| 投球段 | 140ms × 9 帧 | 1.26 秒（投打慢 2 倍，2026-10-16 用户定档） |
| 挥棒段 | 140ms × 3 帧 | 0.42 秒（同上） |
| 捡球 / 传球 | 1120ms（`TICK_MS`＝`TICK_SECONDS` × 2） | 捡球最多 20 拍，即 22.4 秒 |
| 跑一个垒 | 7 拍（速度 5） | 地面 / 传球阶段 7.84 秒；飞行期间连续跑满则滚地 / 平飞 / 高飞分别 12.32 / 13.44 / 15.68 秒 |
| 盗垒 | 12 帧 × 140ms | 1.68 秒（与投打动画同时推进） |
| 两边交牌后的倒数 | 1000ms 一跳 | 3 秒（"准备时间"，**不跟着慢放**） |

**慢放只拉长每拍时长，不改任何拍数**：判定次数、投球距离公式与跑者所需拍数不变。
`throw_ticks` 仍按基础 `TICK_SECONDS` 算拍数，实际传球耗时为 `ticks × TICK_MS`；
跑者在飞行期间按该球型的飞行拍长前进，落地后则按捡球 / 传球拍长前进。
跨阶段时，总用时由各阶段剩余拍数及对应拍长共同决定。

- 球从 1 号位起飞，`ball_position` 保证每拍只前进一格（落点 8 的球就是 1→2→…→8），
  `flight_steps(kind, landing)` 给出拍数（＝跨格数）与每拍毫秒数。
- 野手的"追上追不上"只由一个速度决定：`flight_run_speed(speed, ticks, tick_ms)`＝
  （整段飞行总共 3 格，速度 ≥7 双倍）÷ 飞行总时长（格/秒），**匀速、连续**地跑，
  球飞得远不会让他更快。**没有总额度上限**：
  追球是持续动作，追得慢是因为球比人快，而不是跑到某一格被系统停住。
  （2026-10-15 从 5 格降到 3 格：模型实测只让落地率从 19% 到 19% 上下——**追球限额不是卡点**，
  真正的卡点是下面的接球覆盖：判"够得着"的比例高达 96%。）
- 捡球阶段每拍 1 格（速度 ≥7 两格）：`ground_run_speed`＝这个数 ÷ 一拍的秒数。
- 接球覆盖（2026-10-21 用户定：回车起跳，取代「普通 / 跳跃 / 飞扑」三选一）：
  不起跳 = `BASE_COVERAGE`＝1 格（小范围、稳）；球到的那一刻正好在空中 = 再 `+LUNGE_REACH_BONUS`＝2 格，
  即 3 格，但脱手概率额外 `+LUNGE_MISS`＝20%（大范围、糙）；布阵加成与守备 ≥ 7 的 +1 照旧。
  起跳要在球到之前 `FIELDER_AIR_SECONDS`＝1 秒内按下才算，跳完要再缓 `FIELDER_REST_SECONDS`＝1 秒
  （见上文「飞行与捡球操作」）；这几个数都是手感参数，实机觉得难按 / 太宽松时先调它们。
  **只要落点差 ≤ 覆盖格数就算"够得着"**，所以野手站在落点 3 格外在空中也可能接住——
  这是击进场内的球大量被接杀的原因（真实棒球约 30% 落地）。
  按球型叫名字：滚地球起跳＝飞扑、空中球起跳＝跳起（只用于播报）；滚地球仍永远不可能被接杀。
- 落点范围的初始宽度是**击球质量的后果**：刚出手时半宽 `SPAN_HALF_MIN`＝1.2 格（最软）
  到 `SPAN_HALF_MAX`＝3 格（最结实），范围正中偏离真落点 25%–85% 半宽（`SPAN_OFFSET`），
  随球飞近线性收窄、正中线性挪向真落点（`HitBall.span_at / estimate_at`）。
- 用户觉得节奏还是不对时，先改这里的 X 与"一格毫秒"，别去动相对速度——
  改倍率只会让一切变慢/变快，改相对速度会破坏守备与跑垒的平衡。

## 击球质量（决定球飞多远、落不落地）

| 读准球种 | +14（没读准 −8） |

## 球种（2026-10-15 用户定档：从 3 个加到 5 个，中文 + 英文）

菜单里写中文 + 英文（英文是权威写法），面板上只用中文短名。每个球种都有自己的性格——
速度、变化、控球风险、体力四项至少各差一处，**不允许出现"换了名字但一模一样"的假选择**：

| 球种 | 打者要按的时机 | 球速修正 | 变化权重 | 控球修正 | 体力倍率 |
| --- | --- | --- | --- | --- | --- |

## 挥棒与选球（2026-10-15 用户定档：击进场内要**比现实更多**）

挥棒先判"接不接触得到"。接触率**基础 0.80**（判对球种 + 对上时机时截到上限 0.95）——
用户明确要求球更多留在场上（"打进场内肯定要更多，这样才能加强趣味"），
所以这一档**故意高于真实棒球的 60%**，不是还原现实。没打中时按 **55:45** 分挥空与界外
（2026-10-15 从 40:60 调高：界外球在两好球后是免费的，太便宜会让"接触率低"变得无所谓）。

**惩罚一律是乘法，不能相加**（2026-10-15 修，重要）：读得准的人接触率本来就顶到上限 0.95，
相加的惩罚会被上限整口吃掉——强挥 −10% 变成免费、投手全力 −5% 变成免费、变化球惩罚也免费。
端到端后果：**永远强挥每局 6.70 分 vs 接触挥 2.12 分（3.2 倍）**，强挥成了无条件最优。

| 全力投球 | ×(1 − 5% − (球速−5)×1.5%) |
| 变化球 | ×(1 − (投手变化−5)×2%) |
| 大力挥击 | ×(1 − 25% + (力量−5)×1%) |
| 滚地球 | **+5%**（收着挥、以碰到球为先） |
| 坏球区 | ×(1 − 13%)，大力挥击再 −8%（收棒时不适用） |
| 投手牵制跑者 | ×(1 + 8%) |

改成乘法后实测（2 万球，读准球种 + 时机对、属性全 5）：

| 挥棒 | 挥空 | 界外 | 进场 | 质量 | 本垒打 |
| --- | --- | --- | --- | --- | --- |
| 标准挥击 | 4.2% | 3.5% | **84.2%** | 70.4 | 1.6% |
| 大力挥击 | **16.6%** | 13.9% | **61.1%** | 72.6 | 1.9% |
| 滚地球 | 最低 | 少数 | **最高** | 封顶 44 | 0（一定滚地） |
| 未挥棒（不按） | 0 | 0 | 0 | — | — |

大力挥击＝挥空 4 倍、进场 −23 点，换来质量 +2.2、本垒打 +0.3 点：**要不要冒险看局面**，
不再是无条件最优。滚地球把质量封顶到 44（球型强制滚地）：进场率最高、绝无长打，
它的价值在**打者出局也能把跑者送回去**（三垒有人＝野手选择打点）。挥空 16.6% 与进场 61% 也正好落在真实棒球的量级（20% / 60%）。
**最终平衡实测（真实机器人引擎，双方同策略各打整局）**：标准挥击 0.93 分/局、大力挥击 0.93 分/局
＝ **1.00×**——两种风格期望一样，区别只在方差（大力挥击靠长打与全垒打，标准挥击靠把球打进场地）。
改动前同一测法是 **3.2×**（接触挥 2.12 / 强挥 6.70）。

**滚地球规则改正之后重新实测（20 局机器人对局）**：两侧 48 : 33 分（约每边每局 1.2 分），
比改前的 9 : 10 分（每边 0.45）更接近真棒球；分数上来的地方就是滚地球不再被"接杀"、
变成真的"捡球 → 传一垒"（多数是滚地球出局，快的打者和 25% 的控球结束会变成上垒）。
要压回更低的比分，两个旋钮：野手"控球结束"（拿球不传）的概率，和打者跑一垒所需的拍数。

**选球（eye）有两条作用**（此前它对结果零影响，2026-10-15 修）：

1. **坏球区收棒**：你选了挥棒、但球落在坏球区时，按选球概率及时收住——
   收棒率 = 25% + (选球−5)×6%（夹在 0–90%）；收住这一球就**改按好坏球判**（多半是坏球）。
2. **猜错补救**：猜错球种时，接触率惩罚从 −8% 变成 −8% + (选球−5)×1.2%，
   质量惩罚从 −8 变成 −8 + (选球−5)×2。

- 实测（40 局机器人对机器人，两边代码路径完全一样，乘法惩罚 + 挥空 55% 这一档）：
  每局 1.17 分（改之前是 1.05 分，水位没变）。
- **副作用要知道**：接触率抬高后三振会变少（现在每局约 0.4 次）。要更多三振就得降接触率或
  提高挥空占比，两者会直接减少"球留在场上"的次数。

## 落地之后：捡球 → 传球 → 跑垒

- 球落地**不直接判安打**：先进入捡球阶段（每拍 1120ms，最多 20 拍），野手得跑到落点。
- 落点与垒包的距离按场地坐标算（一格横移 ≈ 5 米；纵深：滚地 25、平飞 45、高飞 65 米；
  垒包坐标：一垒 (19.4, 19.4)、二垒 (0, 38.8)、三垒 (-19.4, 19.4)、本垒 (0, 0)）。
- 传球拍数＝`ceil(距离 ÷（16 + 2.2×臂力）÷ 0.56)`，至少 1 拍；实际每拍 1.12 秒。
  传球菜单会把距离标出来，传球过程有进度条（见「动画」一节），到垒那一拍才判。
- 跑者跑一个垒需要 `max(3, 12 − 速度)` 拍；速度 5 在地面 / 传球阶段需 7.84 秒，
  飞行阶段则按对应球型的每格拍长推进。在球到垒前站稳算安全，
  否则出局（出局 +1）。没人传球或超时＝野手控球，这次击球结束，非出局跑者至少推进一个垒。
- **转传（地面连续双杀）**：在垒上判出局后这一拍不结束——只要还有人被迫在跑，球就停在
  那个垒上（`room.ground.base`，`ball`/`cell` 为 0＝外野线上没有球，阶段显示「转传」），
  按钮换成从该垒算距离的剩下几个被迫垒位，再传一次就是同一拍两个出局（`双杀`）。
  传杀第三人（第三出局）时不再开转传。
- 机器人野手捡到球后**仍然是随机挑一个垒包传**（2026-10-15 用户裁定，见
  [game-design-principles](./game-design-principles.md#bot-behaviour)）：机器人防守故意偏弱，
  所以人机对局里封杀与转传双杀很少出现，这套机制主要在你当守方时用。

## 高飞牺牲打（接杀后触垒进垒 / 2026-10-15 用户要求）

- 高飞被接杀后，**没提前离垒**的人还站在原垒：这时开一个触垒窗口（阶段 `tag`，棋盘下方还是
  攻方那一排「撤回 / 停止 / 前进」，光标回到「停止」，状态页阶段显示「触垒」）。
- 这是**决定阶段，不是定时动画**：没有 tick，攻方不按就一直等（和投球 / 打击一样）。
  机器跑者一定会自己选一个（`_bot_tag`），所以机器人对局不会卡住。
- 选「停止」或「撤回」＝全部回原来的垒，这一拍结束。
- 选「前进」：最前面那个跑者冒险多一个垒，球马上从野手位置传到他会去的那个垒
  （走同一套传球进度条与距离算法）；人先到＝安全（三垒那人跑回来＝牺牲打得一分），
  球先到＝触杀出局。其余的人各跟一个垒，但这次传球只够杀一个人。
- 第三出局已经出现（接杀即第三出局）时不开这个窗口。
- **这一拍的第三出局是封杀或打者出局时，同一拍跑回来的分不算**（美职棒记分规则，`_end_play(count_runs=False)`）。

## 出局方式（真实棒球规则 / 2026-10-15 用户要求核准）

| 出局 | 怎么发生 | 播报 |
| --- | --- | --- |
| 三振 | 3 好球（两好球后界外不加） | `挥空 三振 1出局 时机提前 预判错误` |
| 接杀 | 野手在落点把球接住（含跳跃 / 飞扑） | `接杀 落点中线 野手中线偏右 跳起恰好 1出局`（没起跳就没有 `跳起…` 那一段），之后只列没说过的结果 |
| 双杀 | 接杀且有人提前离垒（没回垒）时再带走一个；接杀前已两出局不再双杀 | `双杀 落点… 野手… 2出局`，之后列出那个回垒不及的人 |
| **封杀** | 打者把垒上的人挤着往前跑（被迫进垒），球先到那个垒＝出局；**滚地球打者在一垒也是封杀** | `封杀 二垒 一垒跑者 1出局` |
| **滚地球出局** | 滚地球落地（不可能被接杀）→ 野手捡球传一垒，球到得比打者快 | `滚地球 落点中线 野手中线 飞扑恰好` + `传一垒 27.5米` + `封杀 一垒 打者 1出局` |
| **触杀** | 不是被迫、自己多跑的（盗垒、多要一个垒），球到垒时人还没回来＝出局 | `触杀 三垒 二垒跑者 1出局` / `盗垒失败 触杀 本垒 三垒跑者 1出局` |
| 保送 | 4 坏球，打者上一垒；只推进被迫移动的跑者 | `收棒 坏球 坏球区 保送`，随后只列被挤动的跑者：`一垒跑者上二垒` |
| 失误 | 野手脱手：球滚开，垒上的人各多跑一个垒 | `落地 落点… 野手… 失误` |

- 被迫进垒由 `rules.forced_bases` 判定（打者上一垒 → 一垒的人被挤 → 再挤下一个），
  开打后 `bases` 会清空，所以判定用跑者身上的起点垒重建。
- **本作不做的**：内野高飞球（场地只有外野线）、触身球、暴投 / 捕逸、妨碍与阻挡、三杀。
- 地面连续双杀（先传二垒再转一垒）与高飞牺牲打（接杀后触垒再进垒）已按上面的规则实现；
  转传与牺牲打的简化：防守方不会被强制，攻方只赌最前面那个跑者（其余跟一个垒）。
- 实测（机器人整场压测 8 局）：每局约 14 个击出球，接杀 10、落地 3～4，落地里约 1/4 会真的传球，
  平均每局 2 分。想让捡球/传球更常见，调高"质量越难接"的系数或让落点范围更宽即可。

## 数值

- **局数由房主创建房间时定（2026-10-21 用户定）**：1–9 局任选，默认 3 局；走框架现成的
  `room_settings`（游戏详情里「局数」一项，和 UNO 的 Draw 叠加同一机制）。
  每半局 3 出局；4 坏球保送、3 好球三振、两好球后界外不增好球。
  「末局」就是房主选的最后一局；等候室的「房间」面板写出局数，开局播报写 `开赛 bob 先攻 alice 后攻 共5局`，
  状态面板写 `局数 2/5 ▲`，比分页有 N 列。
- **标准终局（2026-10-17 用户定）**：末局上半结束时主队已经领先，下半局不再进行；
  末局下半主队一取得领先就立刻结束（再见分，不必打满三个出局）；打满仍平手＝平局，不加赛。
  两种提前结束都先在日志里说明原因，再走统一的结算。
- 投手：控球 / 球速 / 变化；打者：力量 / 接触 / 选球；野手：速度 / 守备 / 臂力。
- 属性在对局开始时随机为 3–8，双方可见（相当于球探报告）。
- 体力 100，标准投球 −7、全力 −13；≤35 与 0 时控球与球速各 −1。
- 奖励走 `rewards.json`：胜 150/30、负 60/8、平 90/15（经验/金币，**3 局为基准**）；
  **按局数缩放（2026-10-21 用户定）**：经验、金币、段位分都乘「局数 ÷ 3」——1 局三分之一、
  3 局不变、9 局三倍（段位分走框架现成的 `multiplier`），不然 1 局速刷奖励和 9 局一样；
  打机器人时金币按缩放后经验的 `gold_ratio_bot`（0.15×，和 UNO / Ludo 一致）。

## 一局怎么结束（2026-10-15 用户定档）

- **打满房主选的局数或提前结束**（见「数值」里的标准终局）：正常结算，按 `rewards.json` 与局数缩放发经验与金币，然后回等待室。
  结算时按「播报」一节的格式依次写出：比赛结束 → 逐局比分 → 双方战报（安打 / 全垒打 / 保送 / 被三振）→ 结算结论。
- **放弃比赛**：中止——房间回到等待室、可以重开一局，**双方都不发奖励**（和 UNO / Ludo 一致）。
- **断线**：同样是中止——比赛结束、**不判胜负**、双方不发奖励，只向幸存方播报一句。
- 三种情况都只发一次结果；结算失败按框架的重试机制补发，不重复发奖。
