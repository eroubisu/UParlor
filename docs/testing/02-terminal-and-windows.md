# 02 Terminal, Unicode, and windows

前置条件：至少准备 Nerd Font Mono v3 和一个不含 Nerd Font 的普通等宽字体用于对照。

## UI-01 中文与组合字符

**步骤**

1. 在聊天、用户名、房间消息中输入中文、`e` 加组合重音、全角标点。
2. 打开包含这些文本的列表、详情和聊天历史。
3. 缩小再放大窗口。

**预期**

- 字符不被切半、不重叠，列表列宽和边框保持对齐。
- 组合字符作为一个可见字符移动和折行。

**证据**：88×32 与 120×50 两种尺寸截图。

## UI-02 用户 emoji 隔离

**步骤**

1. 在聊天中发送单码点 emoji、肤色修饰、家庭 ZWJ、旗帜和键帽序列。
2. 打开聊天浮窗并滚动、覆盖另一个浮窗。

**预期**

- 用户内容可显示且不会破坏后续行。
- 内置按钮、棋盘和状态图标仍只使用单色 Nerd Font 字形。

**证据**：脱敏聊天截图；不要使用真实私聊。

## UI-03 Nerd Font 单色着色

**步骤**

1. 使用 Nerd Font Mono v3 启动客户端。
2. 检查在线/离线、通知、游戏、警告、奖杯和棋子字形。
3. 观察同一字形在不同状态下的颜色。

**预期**

- 字形为字体轮廓而非彩色图片，可被 Rich 前景色改变。
- 每个注册字形占一列；飞行棋每个棋盘 cell 保持两列。

**证据**：至少包含在线列表、UNO 和飞行棋各一张截图。

## UI-04 缺少 Nerd Font 的降级

**步骤**

1. 临时切换到普通等宽字体后启动客户端。
2. 浏览登录、大厅、游戏列表。

**预期**

- 可以明确观察到字体依赖，但应用不崩溃、布局不无限扩张。
- 切回 Nerd Font 后无需清理数据即可恢复。

**证据**：记录所用字体及降级表现。

## UI-05 浮窗覆盖中文边框

**步骤**

1. 让底层列表边框和内容包含中文。
2. 在其上打开菜单、通知或设置浮窗。
3. 移动浮窗内光标并关闭浮窗。

**预期**

- 覆盖边界附近的中文不会消失或被空格替换。
- 关闭后底层内容完整恢复。

**证据**：覆盖前、覆盖中、关闭后三张截图。

## UI-06 IME 输入

**步骤**

1. 使用微软拼音在登录、聊天和旅伴输入框中连续组词、选词、退格。
2. 在候选状态下切换窗口焦点，再返回继续输入。

**预期**

- 组合文本不被提前提交；Enter 的选词与发送行为不冲突。
- 焦点切换后无残留候选或重复字符。

**证据**：记录 IME、终端版本和失败序列。

## UI-07 窗口焦点层级

**步骤**

1. 进入 UNO 对局，使用大写方向键依次聚焦棋盘、聊天、日志和操作面板。
2. 聚焦棋盘后打开聊天浮窗，再关闭聊天浮窗。
3. 触发重复登录下线弹窗。
4. 在 UNO 等待房间缩放终端，观察操作面板中的分隔线。

**预期**

- 当前活动窗口内只有接收操作的面板使用亮边框，其余面板使用暗边框。
- 浮窗打开时浮窗亮、底层游戏窗口暗；关闭后游戏窗口原焦点恢复为亮边框。
- 下线弹窗使用亮边框，底层窗口使用暗边框。
- 焦点变化只使用既有灰度层级，不引入新的强调色。
- 操作分隔线随面板宽度变化，始终只占一行且不残留旧宽度。

**证据**：UNO 面板切换、浮窗覆盖和下线弹窗各一张截图。

## UI-08 引擎原语一致性

**步骤**

1. 登录后观察大厅三个面板的第一帧，再依次打开房间搜索、在线玩家、聊天、通知、设置、
   旅伴创建和游戏等待房间。特别观察旅伴和聊天浮窗刚出现的第一帧。
2. 首次显示登录页时，确认用户名输入行可见、分割线位于输入行下方；按 `i` 输入测试账号。
3. 检查每个选项列表、子菜单和确认界面；调整终端宽度并切换标签及浮窗。
4. 在每个可输入界面按 `i` 输入但不提交，按 `Esc` 或 `Ctrl+[`，使用 `j/k` 导航后再按
   `i` 返回。
5. 在长日志或聊天中向上滚动，再触发一条新内容。
6. 分别在同一弹窗中按 `Esc`、`X`、`Q`，确认结果完全相同。在旅伴设置、游戏操作子菜单、
   确认界面和聊天样式候选中选择“返回”或否定选项并按 Enter。
7. 进入游戏等待房间和实际对局，在没有浮窗时分别按 `Esc`、`X`、`Q`；再打开聊天或档案
   浮窗并按相同按键。
8. 按 Space 打开居中的根菜单，用方向键/WASD/HJKL 导航并用 Enter/Z 打开每个入口；
   验证字母入口键不能直接打开窗口。用三套 Shift+方向映射切换多面板焦点。
9. 连续打开聊天、在线玩家和通知浮窗；快速打开后立即关闭浮窗，再缩放终端并重新打开。
   确认底栏模式、位置、徽章和连接状态稳定，无旧窗口内容或中间布局残留。
10. 打开任一浮窗后按 Space，确认根菜单居中覆盖其上；关闭菜单后原浮窗恢复。再从菜单选择
    另一个浮窗，确认新浮窗完成布局后一次替换旧浮窗，屏幕上不叠放两个工作浮窗。
11. 打开在线玩家列表，确认第一位玩家的光标和名片同时出现且第一行位于视口内；在任一选项
    列表的第一项按上、最后一项按下，确认首尾环绕并跳过禁用项。
12. 分别观察登录进入大厅、大厅进入游戏等待室、等待室进入实际对局、对局返回等待室和
    等待室返回大厅；确认旧主窗口保持完整，直到新主窗口按最终尺寸、内容、位置栏、操作和
    焦点一次替换，不出现空白帧、旧位置/旧操作或错误亮边框。
13. 分别打开聊天清空、好友操作、通知操作和退出设置的“是/否”确认，缩放终端并切换选择。

**预期**

- 所有选项使用相同的两列前缀、折行、禁用跳过和 Enter 确认规则；同一上下文刷新保留
  选项，切换上下文聚焦首个可操作项。首次打开此前隐藏的窗口时，中文选项保持横向
  排列，不得逐字纵向堆叠；第一帧就是按最终宽高、标签、输入区和滚动条空间排好的内容，
  不得先闪现乱码、错误折行、错误焦点或错误滚动位置再刷新。
- 大厅第一帧只有房间搜索面板使用亮边框；每个浮窗第一帧也只有当前面板使用亮边框。
  旅伴聊天框线从首次出现起就匹配当前内容宽度，终端缩放后不得保留旧宽度框线。
- 所有分割线随布局变化且只占一行；没有文本拼接的残留横线。
- 输入行与分割线各占一行且互不覆盖；登录页无需切换标签即可看到用户名提示并按 `i`
  开始输入。
- 所有输入框遵循 NORMAL/INSERT 协议；退出 INSERT 后草稿保留，导航立即恢复，返回该
  字段时可继续输入。标签、窗口和提示文字同步更新。
- 阅读历史内容时位置不跳到底部；原本位于底部时继续跟随新内容。
- `Esc`、`X`、`Q` 是同一退出/取消动作的三套键位映射，任何界面都不产生差异。
- 在等待房间或对局中没有浮窗时按这些键，玩家位置和主界面不变；存在聊天、在线、档案等
  浮窗时，只关闭最上层浮窗并恢复原位置界面。
- 所有层级返回都显示为可选行并由 Enter 确认，不存在专用层级返回键。操作说明只出现在
  教程和帮助中。
- 是/否确认界面的否定项承担返回作用，其下不再出现额外的“返回”项。
- 每个是/否确认的问题与选项之间都有一条原生分隔线，缩放后不残留旧宽度文本横线。
- 全局操作只有方向、选择、退出、Space 弹窗和文本输入五类；普通方向只操作当前面板，
  Shift+方向只切换面板，私聊与通知操作均通过 Enter 打开的选项完成。
- 根菜单始终位于当前浮窗上层；普通浮窗之间使用准备后替换，不出现叠窗、空白中间帧、
  左上角残影或最终宽度之外的错误折行。在线列表等待首位玩家名片渲染完成后一次显示光标和
  详情；名片请求失败时在短暂等待后显示稳定空态，不永久遮住原窗口。
- 所有主窗口使用与浮窗相同的离屏测量和原子提交；切换提交前，旧窗口的可见内容、活动焦点
  和输入目标保持一致，提交后才同时切换到新窗口。
- 所有通用选项列表首尾环绕，并继续跳过不可操作项。

**证据**：至少记录一个窄终端折行、一个保留输入草稿、一个保持滚动位置，以及在线列表
首帧或请求失败空态的场景。

## UI-09 全局最小终端尺寸

**前置条件**：客户端处于任意可恢复页面，不在输入密码或 API Key。

**步骤**

1. 将终端调为 88×32，依次打开大厅、设置、UNO 和飞行棋。
2. 缩小到 87×32，再调为 88×31，并尝试导航。
3. 恢复到 88×32。

**预期**

- 88×32 时各页面正常显示，游戏固定区域不重叠。
- 任一维度不足时只显示当前尺寸和至少 88×32 的要求，导航不改变底层状态。
- 恢复尺寸后原窗口、选择、滚动位置和未提交草稿仍在，不发生重建闪烁。

**证据**：两个不足尺寸提示及恢复后原状态截图。
