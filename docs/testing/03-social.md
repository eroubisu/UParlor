# 03 Social and chat

前置条件：账号 A、B 同时在线，账号 C 离线；A 与 B 已互为好友。

## SOC-01 在线与好友状态

**步骤**
1. A 打开在线窗口。
2. B 退出并重新登录。
3. A 刷新/重新打开窗口。
4. 切换到“全部”，连续向下越过一屏，再连续向上；滚动过程中直接关闭窗口。

**预期**
- B 的在线状态及时变化，C 不被误标在线。
- 名片、好友标识和实际账号一致。
- 光标始终留在可见区域，列表只按导航方向平滑移动，不在顶部和底部之间抖动。
- 关闭窗口后左右两栏同时消失，底层界面立即完整恢复，不残留名片内容等待下一次操作。

**证据**：B 上下线前后截图，以及长列表导航和关闭后的短录屏。

## SOC-02 好友邀请闭环

**步骤**
1. 使用尚未互为好友的两个测试账号发起邀请。
2. 接收方分别测试拒绝与接受。
3. 重登双方账号。

**预期**
- 通知只出现一次；接受后双方好友列表一致并持久化。
- 拒绝不会建立单边好友关系。

**证据**：脱敏通知和重登后的好友列表。

## SOC-03 世界与房间聊天

**步骤**
1. A、B 在大厅互发中文、长文本和用户 emoji。
2. 两人进入同一游戏房间并发送房间消息。
3. 其中一人离开房间后继续发送世界消息。

**预期**
- 世界/房间频道不串线，时间和发送者正确。
- 长文本折行不破坏后续消息。

**证据**：使用无隐私的固定测试文案截图。

## SOC-04 私聊与未读

**步骤**
1. A 关闭聊天浮窗，B 连续发送两条私聊。
2. A 检查未读徽章并打开对应会话。
3. A 回复后关闭再重开聊天窗口。

**预期**
- 未读数准确，打开后清零。
- 会话对象和消息顺序与服务端规范记录一致，不混入其他联系人或产生客户端持久副本。

**证据**：未读前后截图，消息内容使用测试占位文本。

## SOC-05 游戏邀请选择

**步骤**
1. A 创建游戏房间并打开邀请菜单。
2. 检查候选列表，邀请 B。
3. B 接受；再测试过期或已处理邀请。

**预期**
- 普通邀请候选优先只列好友。
- 选择后自动发送完整命令，不要求手输玩家名。
- 邀请不能被重复接受。

**证据**：候选列表和双方最终房间状态。

## SOC-06 并发好友变更

**前置条件**：账号 A、B、C 同时在线且互非好友；这是三客户端并发用例。

**步骤**
1. A、C 尽量同时向 B 发送好友申请。
2. B 依次接受两条申请，重登三个账号。
3. B 连续移除 A、C，再次重登三个账号。

**预期**
- B 收到两条且各仅一条申请，不因并发覆盖其中一条。
- 接受后 A-B、B-C 双方列表对称，不出现单边好友。
- 移除后三个账号均无残留关系，在线列表和持久化结果一致。

**证据**：B 的两条申请、两轮重登后的三方好友列表截图；不记录密码。

## SOC-07 私聊会话清空

**前置条件**：A 与 B 有服务端私聊历史，并可检查测试服 DM 文件的哈希和修改时间。

**步骤**
1. A 打开与 B 的私聊并选择“清空记录”。
2. 关闭并在不退出账号的情况下重新打开该会话。
3. B 向 A 发送一条新的无隐私测试消息。
4. A 退出账号再重新登录。

**预期**
- 清空后当前会话不显示旧消息，重新打开也不立即回填。
- 服务端 DM 文件内容、哈希和修改时间不因清空动作变化。
- 新消息可以显示；重新登录创建新 State 后，规范服务端历史可再次加载。

**证据**：清空/重开/新消息截图，以及清空前后的文件哈希与修改时间；不得记录真实私聊。

## SOC-08 聊天日志日界轮转

**前置条件（破坏性）**：仅使用已备份的隔离测试服和脱敏测试消息，并可临时控制日志目录权限。

**步骤**
1. 在隔离测试服将北京时间推进到 04:00 前，分别发送世界聊天和私聊。
2. 保持服务端运行，越过 04:00 后再次发送两类消息。
3. 临时令世界聊天 history 目录不可写，发送一条脱敏测试消息，再恢复写入并重发。
4. 检查活动日志和 history 目录。

**预期**
- 04:00 前后的消息分别保存到两个逻辑日期。
- 首条新日期消息触发旧日志归档，无消息丢失、重复或跨日混写。
- 归档失败的消息明确提示失败且不广播；恢复后重发成功，旧日志和新日志仍按日期分离。

**证据**：脱敏后的失败提示、活动/归档文件名和消息 ID。

## SOC-09 玩家聊天样式

**前置条件**：账号 A、B 同时在线；A 至少拥有两个称号；使用 Nerd Font Mono v3。

**步骤**
1. A 按 `Space`，用方向键选择“档案”并确认打开；确认直接按 `P` 不会打开档案。选择
   “聊天样式”并确认打开独立窗口。
2. 依次切换“身份、颜色、连接、外框、确认”标签，选择聊天称号、各板块前景/背景色、
   外框色、正文色、左右端不同形状、板块间分隔及直角/圆角外框；始终检查窗口下部预览。
   分别查看尖角、垂直、斜线、圆弧和 `░▒▓` / `▓▒░` 模糊渐变，再确认保存。
3. 在颜色候选中只移动光标、不确认，检查下部预览；再反复缩小和放大终端。选择“返回”
   并按 Enter 回到字段列表。分别重新打开窗口并用 `Esc`、`X`、`Q` 关闭。
4. A 在世界、房间和与 B 的私聊中分别连续发送两条消息；B 在对应界面观察。
5. B 插入一条消息后，A 再发送一条长中文消息和一条足以挤开时间的长消息。
6. A 修改配色并保存；确认修改前发出的消息立即以新样式正常重绘，再发送一条消息。
   B 重开聊天窗口并加载包含旧版等级前缀发送者的历史。

**预期**
- 保存前不发送更新；保存后 A、B 看到相同的最新样式。
- 独立窗口上部选项可滚动，下部预览保持可见；连接名称和字形与 Powerlevel10k 语义一致。
- 光标移动到任一候选时预览立即采用该候选，但选择“返回”前未确认的候选不写入草稿；
  终端尺寸变化后预览按新宽度完整重绘。`Esc`、`X`、`Q` 关闭窗口的效果完全相同。
- 同一发送者相邻消息共用一个完整外框；其他发送者插入后开启新框。
- 标题固定为单行“玩家名、专用聊天称号、等级”，不能伪造未拥有称号、名字或等级。
- 每条消息以灰色显示秒级时间；最后一条正文和时间嵌在下边框，放不下时仅时间另起底边行。
- 修改样式后，新旧格式历史均以规范发送者身份和最新样式重绘，不出现乱码或双重身份；
  Unicode 折行、渐变和两种外框均不破坏固定宽度。

**证据**：A 的向导预览，以及 A、B 对同一组无隐私测试消息的脱敏截图。

## SOC-10 世界聊天投影与历史分页

**前置条件**：世界聊天至少有 25 条无隐私测试消息，账号 A 已登录。

**步骤**
1. 打开世界聊天，记录首次显示的消息数量；关闭并重新打开聊天窗口，再退出登录并重新登录。
2. 导航到聊天顶部，再按一次向上；观察顶部行，再按一次向上。重复该过程两次。
3. 切到“设置”，选择“清空聊天记录”并确认；关闭窗口、重新打开，再退出并重启客户端登录。
4. 让账号 B 在清空后发送一条新消息，再重复顶部历史加载。
5. 在世界、房间和游戏内聊天中分别重开窗口并调整终端宽度。

**预期**
- 每次首次打开或重登最多显示最后 16 条；第一次越过顶部只显示“向上加载历史消息”，
  第二次才加载此前 8 条，之后按同一节奏继续。
- 清空不改动服务端日志；A 重开、重登和重启后默认仍看不到清空边界之前的消息，但能看到
  B 后续发送的新消息。A 主动向上分页时可以再次读取边界之前的记录；再次重开聊天后仍恢复
  清空后的默认投影。
- 服务端返回空页时，第二次向上后直接保持显示“没有更早的历史消息”，不先让提示消失，
  也不要求第三次向上。
- 所有聊天窗口在显示和缩放后按实际宽度重绘，中文、Nerd Font 字形和外框不出现乱码、
  竖排或沿用隐藏窗口的窄宽度布局；历史响应在“设置”标签可见时到达也遵守此规则。

**证据**：初始、两次分页、清空后重启及新消息到达后的脱敏截图。
