# 05 Ludo

前置条件：至少一个玩家和一个 Bot；多人同步用 A、B。

## LUD-01 创建、准备与 Bot

**步骤**

1. 选择休闲/竞技和 2–4 人上限后创建房间。
2. 添加、踢出 Bot；让 B 加入、准备和取消准备。
3. 分别以房主和非房主检查操作列表。
4. 未满房间时选择“开始”并返回。

**预期**

- 设置、座位和颜色分配稳定。
- 权限与准备状态正确同步，Bot 不成为意外房主。
- 未满员时操作面板显示当前人数/房间人数和“返回”，不能开始；提示与取消结果均写入记录栏。
- 对局开始和每次轮转不产生旅伴通知；整局只在结束时产生一次。

**证据**：双方等候室截图。

## LUD-02 棋盘布局与掷骰

**前置条件**：终端至少为 88×32，使用 Nerd Font Mono v3。

**步骤**

1. 开始对局并连续掷骰。
2. 在 88×32 和 120×50 下观察 19×19 棋盘。
3. 检查四种棋子、机场、赛道、跑道、跳点和终点。
4. 投骰后立即观察操作区，直到服务端返回骰子和可移动棋子状态。

**预期**

- 棋盘行列不漂移，所有字体图标保持单色且可着色。
- 顶部记录栏保持不变；左栏只显示完整 19×19 棋盘、原生分隔线和固定 3 行游戏操作区，棋盘和操作区均没有多余滚动条。
- 右栏依次显示游戏状态、聊天和总高 6 行（外框 2 行、内容 4 行）的房间操作；游戏状态按玩家数在 4–7 行之间变化。
- 当前玩家、骰子、各玩家颜色/名字和控制按钮同步。
- 状态面板标题只显示“状态”且没有滚动条；玩家保持单列，每行显示该玩家在机场、赛道、跑道和完成区的棋子数量。
- 投骰等待期间操作按钮保持原内容和位置，仅暂时不可重复提交；服务端状态到达后恢复操作。
- 圆形、菱形符号不撑大棋盘 cell。

**证据**：两种尺寸下的完整棋盘。

## LUD-03 选择与移动动画

**步骤**

1. 触发多个可移动棋子的情况。
2. 使用左右键选择不同棋子并确认。
3. 动画播放期间尝试导航。

**预期**

- 落点预览、路径、闪烁和所选棋子一致。
- 棋子本体始终稳定不闪；同一时刻只有当前选中棋子的黑色路径和落点闪烁，左右切换后立即转移。
- 动画不跳帧覆盖最终服务端状态；结束后按钮恢复。

**证据**：选择前、动画中、落点后三个状态。

## LUD-04 碰撞、跳跃与完成

**步骤**

1. 使用 Bot 或重复局面覆盖起飞、同格碰撞、JP 跳跃、进入跑道和到达终点。
2. 让黄色棋子落在黄色跳格，观察它逐轨道格移动到下一黄色格。
3. 观察被撞棋子与当前回合。

**预期**

- 服务端规则和客户端图形一致；棋子固有颜色始终保留。
- 黄色同色跳跃显示每一个中间轨道格，不直接闪到最终黄色格。
- 排名只记录一次，完成棋子不能再次移动。

**证据**：每种特殊移动的前后状态。

## LUD-05 结算与竞技奖励

**步骤**

1. 完成一局休闲模式和一局竞技模式。
2. 比较各玩家排名、经验、金币和段位变化。
3. 重登并检查持久化。

**预期**

- 排名顺序一致；奖励不重复且符合 `rewards.json`。
- 竞技段位只在适用模式变化，重登后数据不回退。
- 从对局返回等候室时，棋盘保持最后完整帧直到等候室离屏完成并一次替换；从房间返回大厅时同样不出现清空后的房间中间帧。

**证据**：脱敏结算和重登后状态。

## LUD-06 Bot 回调与断线

**步骤**

1. 创建含多个 Bot 的对局，让其连续运行至少五轮。
2. Bot 计算期间让真人玩家断线。
3. 观察服务端是否继续响应其他客户端。

**预期**

- 无死锁、并发异常或断线后的延迟 Bot 操作。
- 房间和玩家映射被一致清理。

**证据**：服务端日志和幸存客户端状态。

## LUD-07 同房间重赛与成员变化

**前置条件**：A、B 和至少一个可替换的玩家或 Bot。

**步骤**

1. 完成一局并记录颜色、排名和最后一次移动。
2. 不解散房间，以原成员开始第二局并完成首回合。
3. 返回等候室，替换一名成员，再开始第三局。

**预期**

- 第二局使用全新棋盘、排名、骰子、回合、动画序号和颜色映射。
- 第二局首回合不会因旧排名立即结束或重复奖励。
- 第三局颜色正反向映射只包含当前成员。

**证据**：三局颜色分配、第二局首回合与第三局玩家列表。

## LUD-08 交互、动画与会话隔离

**前置条件**：两个独立客户端会话 A、B。

**步骤**

1. A 触发多棋子选择和移动动画，B 同时操作另一房间。
2. A 动画播放中退出房间或切换账号。
3. 等待超过一条完整移动动画和闪烁周期。

**预期**

- 光标、按钮、落点、闪烁和动画只影响其所属会话。
- A 退出或账号替换后，旧定时回调不恢复旧棋盘或污染新会话。
- B 的交互和动画连续且不被 A 重置。

**证据**：A 退出前后和 B 同期状态的脱敏截图。

## LUD-09 结算保存失败恢复

**前置条件**：隔离测试服可令第二名真人玩家的首次结算存档失败一次。

**步骤**

1. A、B 完成一局，在保存 A 成功后令 B 的首次保存失败。
2. 不发送任何游戏命令，等待服务端自动重试。
3. 返回等候室并重登 A、B。

**预期**

- 失败期间房间保持结束状态，不开放下一局命令。
- 延迟重试后两人自动收到结算并返回等候室。
- A、B 奖励各提交一次；重登后数值不重复。

**证据**：脱敏服务端重试日志、两端结算和重登后状态。
